# AIHub 71806 Local RAG Design

## 목적

AIHub 71806 심리상담 데이터를 상담 응답의 보조 근거로 사용하되, 원천 상담 전사와 민감한 사례 내용은 로컬 밖으로 노출하지 않는다. 이 RAG는 확정 진단기가 아니라 대화 기반 상태 추정, 상담 흐름 선택, 요약 보고서의 보조 신호로만 사용한다.

## 현재 구조

- 원천 위치: `aihub_71806/api_download/unzipped`
- 인덱스 생성: `src/aihubRag.js`
- 배포용 파생 인덱스 생성: `src/aihubRagExport.js`
- 로컬/배포 RAG parity 평가: `src/runAihubRagEvaluation.js`
- 서버 연결: `src/server.js`
- 상담 턴 결합: `src/counselor.js`
- 공개 상태 필터: `src/status.js`
- 시뮬레이션 연결: `src/simulation.js`

앱 시작 시 라벨 JSON과 전사 TXT를 스캔해 메모리 인덱스를 만든다. TXT 원문은 저장하지 않고, 내담자 발화에서 수면, 불안, 우울, 중독, 자해, 상실 같은 검색 신호 카운트만 추출한다. 라벨 JSON에서는 진단 점수, 내담자 라벨, 상담사 개입 라벨, 정제된 요약만 사용한다.

배포 환경에서는 원천 폴더를 직접 올리지 않고 `node src/aihubRagExport.js`로 생성한 `app_data/aihub-rag-index.deploy.json` 같은 비식별 파생 인덱스를 사용한다. 서버는 `AIHUB_RAG_INDEX_PATH`가 있으면 원천 폴더 대신 이 파생 인덱스를 로드한다. 파생 인덱스에는 원천 파일명, 로컬 경로, case key, 원문 발화, `내담자:`/`상담사:` 전사 마커를 포함하지 않는다.

## 개인정보 경계

기본 정책은 `summary_only`다.

- UI와 `/api/status`에는 로컬 경로, `records`, 사례 원문, 파일명, 사례 ID를 내보내지 않는다.
- `/api/chat` 응답의 evidence와 상담 요약 보고서에는 매칭 개수와 조건 분포 같은 공개 요약만 포함하고, 사용자용 요약과 상담자 검토용 요약에는 `ANXIETY` 같은 내부 분류명을 직접 쓰지 않는다.
- RAG 조건 분포는 내부 조건 코드와 함께 `불안 관련`, `우울 관련`, `중독/충동 관련`, `일반 스트레스 관련` 같은 공개 표시 라벨을 제공한다.
- 타인의 자살·사망 소식처럼 애도 맥락이 분명한 경우에는 내부 매칭 조건이 중독/우울 후보와 섞여도 공개 조건 분포를 `상실/애도 관련`으로 묶어 표시한다.
- 성폭력·학대·해리감처럼 트라우마 맥락이 분명한 경우에는 내부 매칭 조건이 불안/우울 후보와 섞여도 공개 조건 분포를 `트라우마 반응 관련`으로 묶어 표시한다.
- 외부 LLM 프롬프트에는 기본적으로 공개 요약만 들어간다.
- 상세 RAG 요약을 외부 LLM에 보내려면 `ALLOW_REMOTE_RAG_CONTEXT=true`를 명시해야 한다.
- 안전 우선 분기에서는 RAG 검색 자체를 생략한다.

현재 정규식 기반 비식별화는 전화번호, 이메일, 식별번호, 계좌, 카카오ID, 이름 필드, 학교, 직장, 일부 주소를 제거한다. 자유 문장 속 모든 이름과 주소를 완전하게 제거하는 수준은 아니므로 배포 전 추가 검수가 필요하다.

배포용 인덱스는 `validateDeployableAihubRagIndex`로 별도 검증한다. 검증은 허용되지 않는 record 필드, 원천 파일명/경로, 전사 화자 접두어, case identifier 형태 문자열을 차단한다. 현재 로컬 데이터 기준 배포용 인덱스 1,501건 생성 결과 validation issue는 0건이다.

## 검색 방식

`buildAihubRagContext`는 최근 사용자 발화에서 검색 특징을 추출하고 각 사례에 점수를 준다. 현재는 최근 사용자 발화 6개까지를 비공개 검색 텍스트로 합쳐 사용한다. 이 검색 텍스트는 점수 계산에만 쓰고 UI, API 응답, 문서, 외부 LLM 프롬프트에는 그대로 노출하지 않는다.

- 텍스트 토큰 일치
- 라벨 점수 일치
- 전사 기반 신호 카운트
- 우울, 불안, 중독, 상실, 자해 관련 조건 가중치

결과는 최대 3개 요약 사례로 제한한다. 매칭이 없거나 인덱스가 비어 있으면 앱은 기존 상담 지식과 안전 규칙으로 정상 동작한다.

수면 문제처럼 불안, 우울, 중독, 자해, 상실 등 특정 조건을 강하게 가리키지 않는 모호한 입력은 점수 상위 사례가 한 조건으로만 몰릴 수 있다. 이 경우 `selectRagMatches`가 먼저 서로 다른 조건의 후보를 고르고, 남은 슬롯을 점수순으로 채운다. 반대로 자해, 상실, 명시적 불안처럼 조건 신호가 뚜렷한 입력은 기존 점수 우선 순위를 유지한다.

타인의 자살·사망 소식을 들었다는 입력은 `자살`이라는 단어가 있어도 사용자 본인의 자해 의도가 따로 드러나지 않으면 `self_harm` 검색 특징을 제거하고 상실/애도 맥락으로 검색한다. 반대로 `나도 죽고 싶다`, `나도 따라가고 싶다`처럼 사용자 본인의 위험 의도가 함께 있으면 안전 분기에서 RAG를 생략한다.

성폭력, 학대, 침투 기억, 해리감 표현은 `trauma` 검색 특징으로 다룬다. 이 특징은 확정 진단을 의미하지 않고, 공개 근거와 요약 보고서가 일반 불안/우울 후보로만 좁혀 보이지 않게 하는 표시 보정에 사용한다.

트라우마 공개 뒤 몇 턴이 지나 사용자가 `정상은 아닌 거죠?`처럼 짧은 상태 질문을 하더라도, 최근 6개 사용자 발화 안에 남아 있는 최초 공개 맥락을 함께 검색해 RAG 근거가 최신 짧은 문장만 보고 흔들리지 않게 한다.

## 다음 개선 후보

- 비식별화 테스트를 실제 표본 기반으로 더 늘린다. 현재는 배포용 인덱스 유출 검증과 일부 한국형 개인정보 패턴 테스트가 있다.
- RAG 매칭 품질 평가용 고정 시나리오 세트를 더 확장한다. 현재 8개 parity 시나리오에서 로컬 원천 RAG와 배포용 RAG의 top condition/query feature 일치율은 100%다.
- 장기적으로는 로컬 벡터 인덱스나 SQLite FTS로 교체해 재시작 비용과 검색 품질을 개선한다.
